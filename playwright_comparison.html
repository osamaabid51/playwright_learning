Playwright Login — 3 Approaches

Fixture only  ·  POM only  ·  POM + Fixture combined

What each one is
Fixture

Auto-running setup

A block of code that runs automatically before (and after) a test — but only for tests that request it by name in their parameters.

  • Has setup AND teardown
  • Tied to test lifecycle
  • Reusable across all test files
  • Selectors written inline
POM

Page Object Model

A class that wraps all the selectors and actions for a specific page. You call its methods manually inside your test.

  • No auto-run — you call it
  • Selectors in one clean place
  • Easy to update if UI changes
  • No teardown built in
POM + Fixture

Best of both

The fixture handles auto setup/teardown. Inside the fixture, it uses the POM class to perform the login — so selectors stay clean and the test stays simple.

  • Auto setup via fixture
  • Clean selectors via POM
  • Test file stays minimal
  • Most scalable approach

  loggedInPage: async ({ page }, use) => {
    // SETUP — written inline here
    await page.goto('/login');
    await page.fill('input[type="email"]', 'user@test.com');
    await page.fill('input[type="password"]', 'pass123');
    await page.click('button[type="submit"]');
    await page.waitForURL('/dashboard');
    await use(page); // test runs here
    await page.close(); // teardown
  }
});

export class LoginPage {
  constructor(private page: Page) {}

  async login(email: string, pass: string) {
    await this.page.goto('/login');
    await this.page.fill('input[type="email"]', email);
    await this.page.fill('input[type="password"]', pass);
    await this.page.click('button[type="submit"]');
    await this.page.waitForURL('/dashboard');
  }
}

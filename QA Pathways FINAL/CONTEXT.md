# Learning Platform — Working Context

How the platform work got here: what was discussed, what was decided and why, and what is open. Newest entries at the bottom. Append only; corrections go in as new entries.

`PLATFORM.md` holds the finalised rules. This file holds the story behind them.

---

## Starting point (16 Nov 2026)

- **Folder:** `Downloads\Learning Paths` holds three self-built study apps plus docs:
  - **CTFL Prep** (ISTQB CTFL v4.0): React app shipped as a Windows exe (Go launcher, `127.0.0.1:47321`) and a PWA. v1.9 is the latest.
  - **Playwright Path** and **Postman Path**: single-file HTML apps. They were later combined into one HTML hub, `learning-paths.html` (the copy named `Learning Paths — Postman and Playwright courses.html`).
  - **Docs:** `APP_STRUCTURE.md`, `DESIGN_GUIDE.md`, the original `PLATFORM.md` (v1, single-shell plan), `design-pattern-review.md`.
- Postman was first built from separate source files (`postman-path-source/`). Since the merge, the HTML files themselves are the source.
- The CTFL React source is not in the folder. Osama has a working CTFL app himself.

## Decisions

| # | Decision | Why |
|---|---|---|
| D1 | Don't rebuild CTFL. The goal is **rules that let any learning path plug into the app**, not a one-off merge | Osama's requirement: build around any learning path and add it to the app |
| D2 | **CTFL is the core/base**, but the contract is symmetric: CTFL can be attached to the Learning Paths app as the base too | Osama: "CTFL is the core, Learning paths can attach to that core, else CTFL can also attach to learning paths" |
| D3 | **One consistent behaviour** across paths and hosts: same screens, labels, lifecycle, metrics and design | Osama: "keeping one consistent behavior obviously" |
| D4 | Delivery: **exe + PWA**, plus proper documentation in the platform spec | Osama's answer on delivery |
| D5 | Rules in three forms: **PLATFORM.md v2**, a **Claude skill** (`build-learning-path`) and a **starter template** with validator and packager | Osama chose all three |
| D6 | Path = portable package `<id>.lpp.js` registered via `LP.register()`. Plugins are framework-free (`LP.plugin` with `mount`/`run`) so React and vanilla hosts share them. Lab checks are declarative JSON | Needed for D2: packages and plugins must run in both a React host and a vanilla-JS host |
| D7 | Course ids fixed to the ones already in use: `ctfl`, `pw`, `api`. One store, `lp-v1`, with migrations from every old key | Keeps existing browser progress |
| D8 | **UI preview gate**: every new screen is shown as a mockup and approved before it is built | Osama: "you'll show me the UI pages before building them" |
| D9 | **Original files are never changed.** All work goes in `Learning Platform\`. Osama's earlier copies left in the root (`course-template\`, `scripts\`, `PLATFORM.v1.md`) stay there | Osama's instruction. The original `PLATFORM.md` was restored after it had been overwritten earlier the same day |
| D10 | Session budget: stay at or under 50% of the session usage limit, then pause | Osama's instruction. Claude cannot see the meter; Osama shares it (11% used at the time of the mockups) |
| D11 | App identity should be **Software-QA themed** | Osama: the app focuses on Software QA paths |
| D12 | **Two study modes per path: Learn step by step, or Assess first.** Placement test (2 bank questions per topic, one module at a time) → Tested out / Review / Learn → study plan. Mocks keep updating the plan | Osama: check where a person stands with mocks and work on those areas directly, to save time and skip topics without skimming the whole syllabus. Added to PLATFORM.md §5.1 |
| D14 | Home screen = Mockup 03 (B journey map + C totals), no connecting line between stations | Osama liked a mix of B and C, then approved 03 with the line removed |
| D15 | **One subtle base colour per path** (`theme.accent`), used only for identity marks: home ring and stage tag, 3 px header rule, switcher dot, path name chip, 3 px card top border, current-topic marker. Actions stay brand blue, status stays status colours, everything else neutral. Colours: CTFL violet `#6A3DAF`, Postman magenta `#B5179E`, Playwright teal `#0E7490`, chosen to stay clear of the brand blue and the status colours (old Postman brown/orange was too close to warning/weak red; the old CTFL blue was the same as the action blue). PLATFORM.md §15, validator checks contrast and distance | Osama: a single subtle base colour per path so the learner knows which path they are on; not overdone; neutral and action colours shared across paths |
| D16 | **Placement test is whole-path, not chapter-wise.** Adaptive 1–2 bank questions per topic (second only to confirm a correct first answer), interleaved, untimed, resumable, "Not sure" counts as wrong; labs not included. Replaces the per-chapter sittings in D12 | Osama: "Assessment should be for whole, not chapterwise. Each chapter/topic already has a practice/lab in the end so why should the assessment be the same?" |
| D17 | **Content is ours; official material is only used from the learner's own files.** Lessons, questions, mocks and labs were researched and written by us (inspired by the official syllabus and other research, close enough to pass the exam, not copied) so they can be monetised without copyright claims. Official mocks are kept for the real-exam experience when available, loaded from the learner's `istqb` folder, never bundled. PLATFORM.md §1 principle 9 | Osama: "the target was to set up our own contents highly inspired by the officials which could be monetized as well as avoid copyright claims… we kept the official mocks if available" |
| D18 | Build from the variants Osama provided as references; no new scope | Osama: "we already know what we are building" |
| D19 | **Content is kept separate from every app, in one standard authoring format** (`courses/<id>/`: Markdown + JSON → validated → one `.lpp.js`). Apps hold no content; content moves between apps by copying the `.lpp.js`, with no code reading. The three existing paths now live in `courses/ctfl`, `courses/api`, `courses/pw` and are edited there from now on, not in the old apps. PLATFORM.md §0 | Osama: "keep the contents separate for the application… a standard way in which the contents will be authored, and then hosted in the application… migrated from one to another app without having to read the code like I've done previously" |
| D20 | **One page frame for every in-path screen**: the same columns, gaps and title placement as Learn (navigation left · content centre · context right). Plugin CSS must stay inside its own root | Osama: different screens used space differently, "no UI consistency between the screens/tabs" |
| D21 | **Separate panes, Option A** (mockup 06): white context pane, grey reading area with white cards, navigation pane tinted with the path colour; each pane scrolls on its own, page does not; thinner scrollbars. Path-colour rule widened for the navigation pane only | Osama: all-grey app was hard on the eyes and not separable; lesson scroll should not move the whole screen; "I like option A better with left panel to be using the color of the learning path" |
| D22 | **Left navigation, option B** (mockup 07): roomier rows (14 px, more row height, wider number column), divider between chapters, only the current chapter expanded; others are one line and open on click | Osama: the left menu felt cluttered, items too close and too small. Chose B over A (all chapters open) |
| D23 | **Exam trick in the right pane**, above the Notebook, on desktop; the lesson card (text, tables, demos) then uses the full centre width. On narrow screens the trick stays in the lesson | Osama (screenshot 5.1.7): empty space beside the demo under the exam-trick rail. Shown mockup 08 (demo full width); Osama chose instead: "Exam trick to be above notes in the right panel" |
| D24 | **Resizable right pane**: drag the divider between centre and right pane; the right pane grows into the centre (limits 280 px right, 420 px centre); keyboard ←/→, double-click resets to 330 px; width remembered | Osama: "allow the right panel to resize dynamically taking space on the left (center section)" |
| D25 | **Postman colour changed to bronze `#9A5B00`** (was magenta `#B5179E`); navigation-pane tint raised from 7% to 11% (hover 17%) | Osama: Postman and CTFL colours were not uniquely identifiable. Options shown in mockup 10 (bronze, olive, change CTFL); a true Postman orange was not offered because it reads like the red Weak status. Osama chose bronze and the stronger tint |
| D26 | **Question/task text layout rule (§10.1)** for every question surface and lab: one list item per line, blank-line paragraphs, the question last, matching lists shown separately, tables rendered; enforced by `validate.py` | Osama (screenshot, practice Q 1.4.2): "options in new line", incl. pairing questions (i./ii. then A./B.); "make that a design rule for mocks, exams, tests, check yourselfs, labs etc." |
| D27 | **Release folder with in-place updates**: `release/` holds the unzipped runnable `QA-Pathways/` plus the three zips (same names, overwritten each release). Updates are written straight into `release/QA-Pathways/app/`; the open app shows an "updated — Reload now" bar. Launcher changes arrive as `QA-Pathways.new.exe` and swap in on next start. Versioning/git deferred | Osama: wants no unzip/re-run after each update; "produce/update the zips, don't keep creating new zips"; "directly write to the folder"; "make a folder for release". Git/rollback: "leave it for now" |
| D28 | **Navigation pane keeps its scroll** when a topic is chosen; only the centre and right panes start at the top. The pane moves only if the new current topic would be out of view (just enough to show it). Clicking the topic you are already on does nothing | Osama: selecting a topic reset the left menu to the top; only middle and right should reset, and not when the same topic is clicked again |
| D29 | **SQL path scope**: "Database Testing with SQL", goal = clearing interviews with confidence. 9 modules (basics, querying, joins, grouping/subqueries, window functions/CTEs, changing data and objects, database testing in practice, NoSQL testing with MongoDB, interview practice), ~36 topics; Interview corner on every topic; MySQL syntax by default with a switch for SQL Server / PostgreSQL / Oracle; fictional Pocket Clinic data; new pieces: SQL lab engine (in-browser), interview flashcards, write-a-query exam questions | Osama: interview focus ("what good is stopping at 5 or doing 6 if they don't help in real world interview questions"), MySQL as base with switch, clinic data, brief NoSQL leaf. Performance testing (JMeter) deferred to a later path |
| D30 | **Interview sets for every path except CTFL** (SQL, Postman, Playwright, later JMeter): basic to advanced, concept and scenario questions, tagged by experience band from 0 to 10+ years; flashcards and mock interview filter by the learner's target band. Built as a shared platform feature (interview corner + cards + mock interview); a path switches it on by adding content | Osama: "add basic to advance interview questions, scenario based ones as well to the paths other than ctfl. Experience level should start from 0yrs upto 10yrs or so" |
| D31 | **Interview question formats**: cards are open-ended (answer aloud, or type in an optional text box), then the model answer with a key-points checklist; the learner ticks what they covered, which sets Got it / Partly / Missed; typed answers saved to the Notebook. Auto-marked only where reliable offline: MCQ, MCQ-style scenarios (best next step), and write-a-query (result rows compared on hidden data). No automatic marking of free text | Osama asked whether questions are open-ended or MCQ; accepted the optional text box + key-points checklist ("OK. great") |
| D32 | **Behavioural questions included** in the interview sets (SQL, Postman, Playwright, later JMeter): answered with STAR (Situation, Task, Action, Result), tagged by experience band like the technical ones; cards show a STAR answer outline and key points to tick, plus tips on what interviewers listen for | Osama: "add the behavioural ones as well" |
| D13 | This file (`CONTEXT.md`) records the conversation and reasoning. `PLATFORM.md` holds only finalised rules | Osama's request |
